# GM-02 공 이동과 코트 바운스

## Unity에서 관찰하기

`Assets/Scenes/DevelopmentCourt.unity`를 열고 ▶를 누릅니다. 공이 포물선으로 날아가고 착지 후 튀어 오릅니다. 공의 자취와 착지 표시로 이동 경로를 확인합니다. 반복 재생은 6초 간격이며 패널에서 해제할 수 있습니다.

| 키/버튼 | 입력 사례 | 첫 착지에서 기대할 결과 |
| --- | --- | --- |
| 1 / In court | x=0에서 상대 코트로 발사 | IN, 이후 두 번째 바운스 구분 |
| 2 / On line | x=4.115에서 발사 | 단식 사이드라인 위이므로 IN |
| 3 / Out | x=4.6에서 발사 | OUT |
| 4 / Net | 낮은 공을 네트 쪽으로 발사 | Net 1회, 공이 되돌아와 자기 코트에 착지하면 OUT |
| 5 / Serve in | 양의 x 서비스 박스를 목표로 발사 | IN |
| 6 / Serve out | 같은 목표에 x=-1.5로 발사 | 잘못된 서비스 박스이므로 OUT |

R은 선택한 사례를 다시 발사합니다. 화면의 IN/OUT은 **첫 착지 결과**입니다. 착지 원과 좌표는 **가장 최근 바운스**를 표시합니다. 이후 바운스가 코트 밖에 떨어져도 첫 착지 결과를 바꾸지 않습니다.

## 좌표와 고정 설정

코트 가운데가 원점이며 y가 높이, z가 코트 길이입니다. Near 플레이어는 z<0, Far 플레이어는 z>0에 있습니다. 마지막 타격자의 반대편을 목표 코트로 판정합니다.

| 설정 | 값 |
| --- | --- |
| 한 번의 물리 tick | 1/60초; Unity Fixed Timestep도 같은 값 |
| 중력 | 9.81m/s² |
| 공 반지름 | 0.12m, 기존 시각용 공 크기에 맞춘 프로토타입 값 |
| 바닥 수직 반발 계수 | 0.7 |
| 바운스 후 수평 속도 유지율 | 0.96 |
| 네트 반발 계수 | 0.35 |
| 정지 기준 | 바닥 반사 직후 수직 속도가 0.35m/s 미만 |
| 단식 범위 | x=-4.115~4.115, 상대편 z=0~11.885 또는 -11.885~0 |
| 서비스 범위 | 선택한 x 반쪽, 상대편 z 길이 6.4m |

설정은 공 오브젝트의 `BallFlight`에서 바꿀 수 있습니다. 시뮬레이션 시작 시 검증한 사본을 사용합니다. 공 크기를 바꾸면 시각 모델의 크기도 함께 맞춥니다. 라인은 포함하며 공의 **착지 중심점**으로 판정합니다. x=4.115는 in, x=4.116은 out입니다.

## 구현 책임

- `BallSimulation`: 공 상태와 중력·반사·접촉 순서를 처리합니다. Unity 물리 콜백이나 점수 계산에 의존하지 않습니다.
- `CourtBounds`: 착지점, 마지막 타격자, 서비스/랠리와 목표 서비스 박스를 받아 in/out을 반환합니다.
- `BallFlight`: FixedUpdate에서 권위 있는 공만 시뮬레이션하고 Transform과 사건을 갱신합니다. 비권위 공에서는 발사·이동·사건 발행이 일어나지 않습니다.
- `BallBounceDemo`: 발사 버튼, 자취, 착지 표시와 관찰용 기록입니다. 게임 규칙과 컨트롤러 입력을 대신하는 개발 도구입니다.

한 tick의 끝점만 검사하지 않고, 중력 궤적이 바닥 또는 반지름만큼 확장한 네트 경계에 도달하는 시간을 구합니다. 가장 빠른 접촉을 처리한 뒤 남은 시간을 계속 진행하여 고속 공의 통과와 같은 tick의 순서 뒤바뀜을 막습니다. 네트는 앞/뒤·윗면·옆면을 가진 단순 직육면체로 근사합니다. 줄별 메시 충돌과 스핀·공기 저항은 범위 밖입니다. 바닥은 y=0의 평면이며 코트 밖에서도 바운스를 계산합니다.

## 다음 모듈에 전달하는 사건

`BallFlight.EventRaised`를 구독하면 `BallEvent`를 받습니다.

| 필드 | 의미 |
| --- | --- |
| RallyId / EventId | 랠리 식별자와 시뮬레이터 내 단조 증가 사건 번호 |
| Kind | Bounce, Out, Net |
| LastHitter | 마지막 타격자의 코트 쪽 |
| Position | 바운스는 바닥 착지점(y=0), 네트는 접촉한 공 중심 |
| BounceCount | 마지막 발사/타격 이후 바운스 횟수 |
| IsInBounds | Bounce 착지점이 해당 목표 영역 안인지 여부 |

첫 바운스가 밖이면 `Bounce(count=1, in=false)` 다음에 `Out`이 한 번 발생합니다. 두 번째 접촉은 `Bounce(count=2)`이며 점수는 올리지 않습니다. GM-04가 사건 ID 중복을 검사하고 득점을 결정합니다. 네트 접촉도 서비스 상태에 따른 fault/let 판단을 직접 하지 않습니다.

새 타격은 `Launch(position, velocity, ShotContext)`로 시작합니다. 바운스 횟수와 tick은 초기화하지만 사건 번호는 되돌리지 않습니다. 온라인 전송 형식과 스냅샷 적용은 GM-07/08에서 연결해야 합니다. 60Hz 계산만으로 플랫폼 간 비트 단위 동일성이 보장되지는 않으며 온라인 물리 확정은 호스트 한 곳에서 수행합니다.

## 검증

Editor를 저장하고 닫은 뒤 저장소 루트에서 실행합니다.

```bash
bash tools/unity.sh check
bash tools/unity.sh test-edit
bash tools/unity.sh test-play
```

EditMode에서는 단식·서비스 경계, 중력 궤적, 반발 에너지, 고속 바닥·네트 접촉, 동일 tick 접촉 순서, 사건 번호와 정지 후 중복 방지를 검증합니다. PlayMode에서는 실제 DevelopmentCourt의 여섯 사례를 실행해 첫/두 번째 바운스, 사건, 오브젝트 위치와 비권위 공의 실행 제한을 확인합니다. 결과 XML과 로그는 `.work/`에 저장합니다.

Unity 화면에서도 ▶ 실행 후 사례를 바꿔 공의 이동·반사와 Console 오류를 확인합니다. 온라인 통신·점수·실물 BLE를 검증한 것은 아닙니다.

참고: [Unity FixedUpdate](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/MonoBehaviour.FixedUpdate.html), [프로젝트 GM-02 과제](https://github.com/digital-tennis/digital-tennis-docs/blob/main/docs/products/digital-tennis-game.md#gm-02).
