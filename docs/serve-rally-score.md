# GM-03/04 서브·랠리 진행과 점수

## 처음 관찰할 흐름

Unity에서 `Assets/Scenes/MatchCourt.unity`를 열고 ▶를 누릅니다. Near의 오른쪽 서브→대각 서비스 박스에 착지→Far와 Near가 각각 두 번 라켓으로 리턴→Far가 다음 공을 놓침→Near가 15–0으로 득점합니다. 득점 표시 1.25초 뒤 같은 서버가 왼쪽 서브 위치로 옮겨집니다. 자동 서브가 켜져 있으면 0.75초 뒤 다음 서브를 시작합니다.

기본 데모는 네 포인트 뒤 Near의 게임 승리로 끝나며 새 경기를 자동 시작하지 않습니다. 이 자동 리턴은 실제 경기 전환을 관찰하는 가상 입력입니다. GM-05에서 실제 타격 범위와 자동 이동을 연결했습니다. [가상 라켓 조작 안내](racket-input-movement.md)를 함께 참고하세요. AI 플레이어는 별도 모듈입니다.

## 수동 조작

자동 서브와 데모 리턴 체크를 끄고 화면 버튼 또는 키를 사용합니다.

| 입력 | 허용 조건 | 결과 |
| --- | --- | --- |
| Space / Serve | 서버의 서브 대기 | 정상 서브 발사 |
| Q / W | 랠리 중 Near의 유효 타격 범위 | Near 포핸드 / 백핸드 |
| E / D | 랠리 중 Far의 유효 타격 범위 | Far 포핸드 / 백핸드 |
| F / Fault serve | 서브 대기 | 잘못된 x 서비스 박스로 발사 |
| L / Let serve | 서브 대기 | 실제 공이 네트 상단을 스치고 유효 박스에 착지 |
| N / Net fault | 회수가 끝난 서브 대기 | 실제 네트 충돌→폴트→볼보이 회수 |
| R / Restart | 경기 실행 중 | 0–0의 새 한 게임 |

더블 폴트: F→첫 폴트 대기→F→상대 15점→다음 서브 대기.

렛: F→첫 폴트 대기→L→렛 판정→볼보이 회수 완료. 점수는 0–0, faultCount는 1입니다. 이후 F를 누르면 더블 폴트가 됩니다. 네트를 건드렸더라도 박스 밖이면 렛이 아니라 폴트입니다.

서브가 날아가는 동안 추가 서브·리턴은 무시합니다. 서비스 첫 착지가 유효해야 리턴할 수 있습니다. 랠리에서는 마지막 타격자의 상대만 반환할 수 있고, Unity 어댑터는 해당 선수 쪽 공의 높이 0.2~2.5 m와 코트 평면 거리 1.5 m를 검사합니다. GM-05의 입력 지연·중복 검사와 자동 이동도 적용합니다.

## 상태와 서비스 박스

| 상태 | 다음 전이 |
| --- | --- |
| WAIT_SERVE | 서버 serve 입력→IN_FLIGHT |
| IN_FLIGHT | 정상 첫 착지→RALLY; 첫 폴트/렛→WAIT_SERVE; 더블 폴트→POINT_END |
| RALLY | 상대 타격으로 계속 진행; 첫 착지 out·두 번째 바운스·정지 판정→POINT_END |
| POINT_END | 공 정지, 득점 1회 확정; 표시 후 다음 rallyId의 WAIT_SERVE |
| MATCH_END | 승리 확정; 재시작 외 경기 입력 무시 |

Near는 z<0, Far는 z>0입니다. 오른쪽 서브에서 Near는 x>0에 서고 Far의 x≤0, z=0~6.4 박스로 보냅니다. 왼쪽은 x 부호를 반대로 적용합니다. Far가 서버인 규칙은 대칭입니다. 박스의 경계선은 포함합니다.

한 게임 동안 최초 서버를 유지합니다. 완료한 포인트 합이 짝수면 오른쪽, 홀수면 왼쪽에서 서브합니다. 폴트와 렛은 포인트가 아니므로 서브 좌우를 바꾸지 않습니다. 세트·게임 간 서버 교대·타이브레이크는 이번 MVP 범위에 포함하지 않습니다.

## 점수와 사건 중복

`TennisScore`는 씬이나 물리 없이 동작하는 값입니다. 누적 포인트 0/1/2/3을 0/15/30/40으로 표시합니다. 양쪽이 3 이상이고 같으면 DEUCE, 차이 1이면 높은 쪽이 AD, 한쪽이 4 이상이면서 차이 2 이상이면 WIN입니다.

```text
3–3 → Near 득점 → 4–3 (AD–40)
    → Far 득점  → 4–4 (DEUCE)
    → Near 두 번 → 6–4 (Near WIN)
```

`PointLedger`는 같은 rallyId를 한 번만 득점시킵니다. 나중에 다른 승자의 중복 판정이 와도 첫 결과를 유지하고, 승리 이후 점수를 바꾸지 않습니다.

`TennisMatch`는 RallyId·ShotId·EventId·LastHitter·상태를 검사합니다. 폴트·렛 이후에도 같은 포인트의 rallyId를 유지하고, 재서브나 리턴마다 shotId를 증가시킵니다. 덕분에 같은 포인트에서 이전 발사의 늦은 사건이 다음 발사를 끝내지 않습니다. 같은 Bounce가 다른 사건 번호로 반복되어도 bounceCount 증가를 확인합니다.

점수는 공의 첫 착지가 out이면 마지막 타격자의 상대, 유효 첫 착지 후 두 번째 바운스이면 마지막 타격자에게 줍니다. 서비스 네트 접촉은 착지까지 기다립니다. 네트 위에서 공이 정지하여 착지가 없으면 폴트이며, 랠리에서 정지하면 착지 이력에 따라 종료합니다.

## 코드와 검증

| 코드 | 책임 |
| --- | --- |
| TennisScore / PointLedger | 점수 표시, 듀스·AD·승리, 포인트 중복 방지 |
| TennisMatch | 허용 입력, 폴트·렛·랠리·득점 상태 전이 |
| TennisMatchController | Unity 공 연결, 득점 후 대기 시간, 가상 입력·화면 |
| BallSimulation / BallFlight | 고정 주기 이동과 충돌 사건; 점수를 직접 계산하지 않음 |

Editor를 저장하고 닫은 뒤 `bash tools/unity.sh check`, `test-edit`, `test-play`를 실행합니다. EditMode는 점수 경계·긴 듀스·중복/상충 득점·입력 제한·폴트/렛·이전 shot/rally 사건을 검증합니다. PlayMode는 실제 경기 씬의 랠리→15–0→반대편 다음 서브, 물리 렛과 더블 폴트, 네 포인트 후 게임 종료를 검증합니다. 기존 공 실험 테스트도 함께 유지합니다.

Unity Play 모드에서도 점수와 다음 서브 위치, Console 오류를 직접 확인합니다. AI와 온라인 릴레이는 연결되어 있습니다. [심판·볼보이 및 온라인 회수 검증](court-officials.md)을 함께 확인하세요. 외장 IMU를 부착한 NU40-DK와의 실물 검증은 별도입니다.
