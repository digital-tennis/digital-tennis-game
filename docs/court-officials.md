# 한 게임 규칙, 심판과 볼보이

## 플레이어가 보게 되는 장면

SinglePlayerCourt와 MatchCourt의 네트 옆 높은 의자에 심판이 앉고 볼보이가 대기합니다. 하단의 CHAIR UMPIRE 패널에 판정과 점수가 표시되며 심판이 팔을 들어 신호합니다. 현재 캐릭터는 기본 도형으로 만든 임시 3D 모델입니다. 음성, 전용 애니메이션 에셋은 포함하지 않습니다.

현재 경기는 단식 **한 게임**입니다. 0→15→30→40, 듀스와 어드밴티지 후 두 포인트 차로 게임을 끝냅니다. 한 게임 동안 서버는 고정이고 포인트가 끝날 때마다 서브 좌우를 바꿉니다. [ITF 2026 Rules of Tennis](https://www.itftennis.com/media/7221/2026-rules-of-tennis-english.pdf)의 규칙 5, 12, 17~25를 기준으로 구현 가능한 공 판정을 확인했습니다. 전체 대회 규칙을 모두 구현한 게임은 아닙니다.

| 상황 | 판정과 다음 행동 |
| --- | --- |
| 첫 서브가 대각 서비스 박스를 벗어남 | Fault, 같은 위치에서 두 번째 서브 |
| 두 번째 서브도 폴트 | Double fault, 리시버가 득점 |
| 서브가 네트에 닿은 뒤 올바른 박스에 첫 착지 | Let, 같은 서브 재시도; 기존 폴트 유지 |
| 서브가 네트에 걸려 넘어가지 못함 | 폴트; 볼보이 회수 후 다음 서브 |
| 랠리 공이 네트에 닿고 정상적으로 넘어감 | 계속 플레이; 볼보이는 대기 |
| 랠리 공이 네트를 넘지 못하고 자기 코트에 착지 | 타격자의 실점; 볼보이 회수 후 다음 포인트 |
| 리턴의 첫 착지가 상대 단식 코트 밖 | Out, 타격자의 실점 |
| 첫 착지는 정상, 이후 밖으로 이동 | 계속 플레이 가능; 두 번째 바운스까지 기다림 |
| 정상 첫 착지 후 리턴 전에 두 번 바운스 | 마지막 타격자 득점; 두 번째 착지의 안/밖은 무관 |
| 경계선에 첫 착지 | In (기존 착지 중심점 판정 유지) |

서브는 첫 정상 착지 이후에만 리턴할 수 있습니다. 유효하지 않은 스윙 입력은 기존 입력 어댑터가 거부합니다. 선수/라켓의 네트 접촉, 신체에 공이 맞는 상황, 풋 폴트, 고의 방해는 현재 자동 이동·타격 모델에서 구현하지 않습니다. 세트·타이브레이크·게임 간 서버 교대와 엔드 교대는 후속 범위입니다. 공 크기와 균일한 네트 높이 등 물리는 기존 게임용 근사값입니다.

## 볼보이가 지켜야 하는 조건

1. 네트에 닿았다는 사실만으로 코트에 들어오지 않습니다. 폴트·렛·포인트 종료 등으로 공이 죽은 뒤 시작합니다.
2. 접근(Approaching)→줍기(PickingUp, 0.65초)→공을 들고 복귀(Returning) 순서로 움직입니다. 반대편 공은 네트 포스트 바깥을 돌아가서 줍습니다. 시작 위치가 순간이동하거나 네트를 가로지르지 않습니다.
3. 회수 중 서브, 자동 서브와 다음 포인트 전환을 막습니다. 공은 볼보이와 함께 움직입니다.
4. 단식 사이드라인 밖으로 복귀한 뒤 서브 위치를 준비합니다. 렛/첫 폴트는 같은 포인트, 더블 폴트는 다음 포인트로 이어집니다.
5. 일시 정지/연결 끊김에는 회수도 멈추고 새 경기에서는 회수 상태를 초기화합니다. 같은 shotId를 두 번 회수하지 않습니다.

볼보이 회수는 경기 연출입니다. 게임의 공 하나를 재사용하므로 네트에 닿은 뒤 죽은 공(렛 포함)을 모두 회수합니다. 현실 경기의 여분 공 교환까지 재현하지는 않습니다.

## 직접 재현하기

Unity에서 MatchCourt를 열고 Play를 누른 뒤 Demo auto serve / racket swings를 끕니다.

1. N 또는 Net fault / ball boy 버튼을 누릅니다. 심판의 Fault 콜을 보고 볼보이가 달려와 공을 줍는지 관찰합니다. 회수 도중 Space/N을 눌러도 새 공이 발사되면 안 됩니다.
2. 복귀 후 N을 한 번 더 누릅니다. Double fault와 Far의 15점을 확인합니다. 회수가 끝난 뒤 왼쪽 서브로 바뀌어야 합니다.
3. L로 렛을 재현합니다. 회수 전후 점수와 폴트 횟수가 유지되어야 합니다. 다시 Space를 누르면 정상 서브와 랠리가 시작됩니다.
4. 기본 데모를 켜서 정상 득점→다음 서브→게임 종료도 확인합니다.

SinglePlayerCourt에서도 N/L과 사용자 키보드 입력이 같은 경로를 사용합니다. 온라인에서는 호스트가 N/L로 서브를 선택하며 양쪽 모두 Q/W로 자신의 라켓을 조작합니다.

## 코드와 온라인 연결

| 코드 | 책임 |
| --- | --- |
| TennisMatch | 순수 규칙과 단조 증가 callId, 판정 종류/문구 |
| BallRecovery | 공이 죽은 뒤 회수 상태/경로; 점수를 바꾸지 않음 |
| TennisMatchController | 공 정지, 회수 중 입력 차단, 회수 완료 후 서브 준비 |
| CourtOfficials | 심판 제스처, 볼보이 위치·줍기 연출, 콜 표시 |
| CourtOfficialsSetup | 기존 씬에 Editor API로 모델/컴포넌트 추가 |
| GamePayload / SnapshotBuffer | 호스트의 officials 상태와 공을 같은 버퍼 시점에 표시 |

게스트는 규칙·공 물리·회수 타이머를 실행하지 않습니다. 스냅샷의 `officials`에 callId/call/text/recovery/runner/completed를 넣고 클라이언트가 유한 값과 범위를 검증합니다. 회수 단계·샷·포인트 경계는 보간하지 않습니다. 기존 서버는 확장 필드를 전달하므로 서버 변경은 필요하지 않습니다. 양쪽 게임은 같은 버전을 사용하세요.

## 반복 검증

Editor를 저장하고 닫은 뒤 다음을 실행합니다.

```bash
bash tools/unity.sh setup       # 기존 씬에 공식 인물만 추가; 재실행 가능
bash tools/unity.sh check
bash tools/unity.sh test-edit
bash tools/unity.sh test-play
bash tools/unity.sh build-mac
node tools/verify-online.mjs --exercise-officials --exercise-reconnect --out /tmp/tennis-officials-proof
```

온라인 검증은 실제 독립 Unity 프로세스 두 개와 형제 저장소의 서버를 사용합니다. 실제 입력 어댑터를 통해 네트 폴트→회수→두 번째 서브 렛→회수→더블 폴트→회수→다음 서브→양쪽 랠리→게임 종료를 실행합니다. 호스트/게스트 JSON과 일반 랠리 및 회수 중 PNG를 저장합니다. 심판 콜 세 종류, 회수 세 단계, 게스트의 실제 볼보이 위치/콜이 수신 버퍼와 같은지, 게스트 물리 tick이 0인지 검사합니다. CLI 인수가 없는 일반 실행에는 검증 입력·자동 종료·화면 저장이 켜지지 않습니다.

이 검증은 같은 Mac의 두 프로세스입니다. 두 물리 Windows PC, 외부 인터넷과 실물 BLE는 별도 검증이 필요합니다.

Mac 화면이 잠겨 있으면 Metal의 첫 화면 표시를 기다리며 창 모드 검증이 진행되지 않을 수 있습니다. 잠금을 해제한 상태로 창 모드를 검증합니다. 자동 실행 환경에서는 같은 명령에 `--headless`를 추가해 화면 출력 없이 두 실제 프로세스의 규칙·상태 동기화를 검사할 수 있습니다. 이 모드는 PNG를 저장하지 않으며 육안 화면 검증을 대체하지 않습니다.

### 검증 기록 (2026-10-15)

- Unity 6000.3.26f1 / macOS arm64: check, EditMode 82/82, PlayMode 19/19, Mac 빌드 성공.
- 두 독립 실행 PID 69200 / 69201, headless 실행: 양쪽 4–1, 호스트 승리, 각 선수 12회 타격, 최대 6회 랠리.
- 네트 폴트→렛→더블 폴트, 볼보이 회수 3회, 포인트 5개와 다음 서브, 강제 소켓 단절 후 epoch 2 재접속 통과.
- 게스트가 수신 버퍼의 심판 콜/회수 단계/실제 볼보이 위치를 652,356번 비교하여 불일치 0개. 호스트 물리 3,240 tick, 게스트 0 tick. 양쪽 실행/프로토콜 오류 0개.
- 창 모드 첫 실행은 Mac이 잠긴 상태라 Metal 화면 표시 대기에서 진행되지 않았습니다. 해당 검증 프로세스만 종료했습니다. 창 모드 육안 확인과 새 PNG 저장은 잠금 해제 후 진행할 항목입니다.
