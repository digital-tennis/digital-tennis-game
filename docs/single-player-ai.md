# AI와 1인 플레이

## 시작하기

Unity **6000.3.26f1**에서 `Assets/Scenes/SinglePlayerCourt.unity`를 열고 ▶를 누릅니다. 이 씬이 기본 빌드 시작 화면입니다. **Near는 사용자**, **Far는 AI**입니다. 기본 국가는 한국/일본이며 C 메뉴에서 선수·코트를 고릅니다. 두 캐릭터의 이동은 자동이며 사용자는 서브와 라켓 타격을 담당합니다.

1. 오른쪽에서 Easy(하) / Medium(중) / Hard(상)를 선택합니다. 난이도를 바꾸면 점수 0–0의 새 경기를 시작합니다. 기본은 Medium입니다.
2. **Space** 또는 왼쪽 Serve 버튼으로 서브합니다.
3. 공이 돌아와 왼쪽 `Near: HIT READY`가 보일 때 **Q(포핸드)** 또는 **W(백핸드)**를 누릅니다. 세기와 좌우·상하 조준은 슬라이더로 바꿀 수 있습니다.
4. 득점 후 다음 서브 위치로 이동하면 다시 Space를 누릅니다. 0·15·30·40·듀스·어드밴티지·승리까지 기존 한 게임 규칙을 사용합니다.
5. R 또는 Restart 버튼으로 다시 시작합니다. 오른쪽 Practice는 기존 가상 라켓 실험 모드로 전환합니다.

1인 모드에서는 자동 서브·자동 라켓 데모를 사용하지 않고, Far용 E/D와 화면 타격 버튼도 비활성화합니다. AI는 별도 정책이 판단하며 사용자와 같은 높이 0.2~2.5 m·기본 코트 평면 거리 1.5 m(캐릭터 수비/스킬 보정)·현재 shot·중복·권위 검사를 통과해야 합니다. 서브 전에 리턴하거나 멀리 있는 공을 강제로 돌려주지 않습니다.

## 난이도

| 화면 | 반응 시간 | x/z 각 축의 이동 오차 | 공별 타격 시도 확률 |
| --- | --- | --- | --- |
| Easy / 하 | 350 ms | ±1.5 m | 65% |
| Medium / 중 | 200 ms | ±0.8 m | 85% |
| Hard / 상 | 100 ms | ±0.25 m | 95% |

오차·시도 여부는 상대의 새 공마다 한 번 결정하며 프레임마다 바꾸지 않습니다. 반응 시간이 끝난 뒤에 이동을 시작하고 유효 범위에 들어오면 한 번 타격합니다. 상 난이도도 실수할 수 있습니다. 확률은 시도 여부이며 경기 승률을 뜻하지 않습니다. 기본 이동 속도는 사람과 AI 모두 5 m/s이며 캐릭터 스피드·체력·활성 스킬로 보정합니다.

AI는 상대가 서 있는 x의 반대쪽을 겨냥합니다. 실제 공 높이·위치와 20° 상향각에서 코트 안으로 떨어질 세기를 계산합니다. 초기 명세의 고정 파워 0.50/0.65/0.80은 상한으로 사용합니다. 서비스 라인 부근에서 고정된 강한 공을 보내면 베이스라인을 넘기기 때문에 위치를 고려해 조정했습니다. 자세한 정책과 수치 검증은 [독립 AI 저장소](https://github.com/digital-tennis/digital-tennis-ai)를 참고합니다.

## 두 저장소의 역할

| 저장소와 코드 | 책임 |
| --- | --- |
| digital-tennis-ai / AiPolicy | 반응, 난수, 의도적 실수, 이동·포핸드/백핸드·세기/조준 결정 |
| digital-tennis-ai / BallPrediction | 중력·반발 계수로 착지와 바운스 후 타격 위치 예측 |
| game / TennisAiOpponent | Unity 상태를 독립 AiState로 변환하고 결정을 RacketInput으로 전달 |
| game / TennisMatchController | 사람/AI 모드, 난이도 선택과 재시작, 자동 이동 및 입력 게이트 |
| game / TennisMatch / TennisScore | 기존 경기 상태·점수·폴트·렛 유지 |

AI는 UnityEngine·씬·게임 어셈블리·점수에 의존하지 않습니다. 게임은 `Packages/manifest.json`과 `packages-lock.json`에 **AI 저장소의 정확한 Git SHA**를 고정해 UPM 패키지 `com.digital-tennis.ai`로 가져옵니다. 로컬 경로나 정책 코드 복사에 의존하지 않습니다. 현재 참조는 AI [PR #2](https://github.com/digital-tennis/digital-tennis-ai/pull/2)의 `2b53ffee3c4e25cf3c6fe34af1c5e52e5b363877`입니다. 스킬 판단 정책을 추가한 미병합 커밋이며, 해당 PR을 스쿼시 병합한 뒤 실제 병합 SHA로 바꾸고 게임 PR을 병합해야 합니다. 저장소 변경 시 새 SHA를 명시적으로 검토해 갱신합니다.

AI 업데이트 번호는 매 프레임 증가하고 시간은 게임의 경과 시간을 사용합니다. 발사 때마다 0으로 돌아가는 공의 Tick을 AI 시계로 사용하지 않습니다. 발사 ID는 rallyId와 shotId를 합쳐 서비스 재시도·다음 포인트의 입력이 섞이지 않게 합니다. AI 입력 세션도 새 경기마다 바꿉니다. 일시정지된 Unity에서는 AI와 물리가 진행하지 않으며, 독립 정책의 PAUSED 상태도 타이머를 진행하지 않습니다.

온라인 상태는 AI 실행을 막습니다. 온라인 전송 자체는 후속 과제이며 모드 선택 화면에 아직 제공하지 않습니다. 개발용 `MatchCourt`와 독립 공 실험 `DevelopmentCourt`도 유지합니다.

## 검증과 재현

Unity를 저장하고 닫은 뒤 저장소 루트에서 실행합니다.

```bash
bash tools/unity.sh check
bash tools/unity.sh test-edit
bash tools/unity.sh test-play
bash tools/unity.sh build-mac
```

EditMode는 패키지가 실제 별도 어셈블리이며 Unity/게임 참조가 없는지, 예측 착지가 실제 공 물리와 일치하는지, AI 샷이 실제 RacketShot·BallSimulation을 거쳐 두 진영의 코트 안에 착지하는지 검사합니다.

PlayMode는 세 난이도 각각 seed 42로 한 게임을 끝까지 진행합니다. AI는 실제 정책으로 Far를 조작하고, Near 쪽은 재현 가능한 가상 사람 입력만 전달합니다. AI·사람 모두 일반 입력 게이트를 사용하며 테스트가 점수나 공 궤적을 직접 바꾸지 않습니다. AI의 실제 리턴, 사람의 리턴, 이동, 득점, 다음 서브, 게임 종료 후 입력 정지를 확인합니다. 별도로 기존 데모가 1인 모드에서 사람을 대신하지 않는지와 온라인 AI 차단을 검증합니다. 생성 로그·XML은 `.work/`에 저장하며 커밋하지 않습니다.

AI 저장소의 `bash tools/check.sh`는 Unity 없이 23개 검증 묶음을 실행합니다. seed 재현, 반응 경계·중복 Tick·동일 공 1회 표본/스윙, 입력 오류, 일시정지·종료·온라인 차단과 각 난이도 10,000개 공의 표본을 확인합니다. 이 결과는 실제 경기 승률이나 실물 IMU 검증과 구분합니다.

전체 프로젝트의 **12일·3명**, **NU40-DK에 별도 외장 IMU 부착** 조건은 유지합니다. 이번 연결은 가상 키보드 입력을 사용합니다. AT-11의 실제 하드웨어 세 난이도 완주는 BLE·외장 IMU 연결 후 별도 확인해야 합니다.

## 실행 기록 (2026-10-15)

- 독립 AI 패키지: .NET 10.0.105의 **23개 검증 묶음 통과**, GitHub Actions 통과.
- 게임: Unity 6000.3.26f1 프로젝트 검증, **EditMode 58/58**, **PlayMode 11/11** 통과. 실제 게임 물리에서 세 난이도 각각 한 게임을 마쳤으며 기존 공·폴트·렛·랠리도 유지했습니다.
- 최종 패키지 커밋은 `0eb9f8b6996feac8430aefde20fbc87682439fe8`입니다. 초기 패키지에서 문서·도구 파일의 `.meta`가 누락된 가져오기 오류를 수정했으며, 이 보완은 정책/테스트 C# 소스를 바꾸지 않았습니다. 갱신 후 새 Editor 실행에서 가져오기 오류가 없음을 확인했습니다.

Unity Editor 화면에서도 자동 데모를 끄고 Space/Q/W 키보드 입력으로 각 난이도 한 게임씩 직접 실행했습니다. 관측 결과는 아래와 같으며 정해진 seed·입력·실행 시간의 단일 사례입니다. 일반적인 승률을 뜻하지 않습니다.

| 난이도 | 포인트 결과 | 사용자 성공 타격 | AI 성공 타격 |
| --- | --- | --- | --- |
| 하 Easy | Near 4–0 Far, 사용자 승리 | 5 | 5 |
| 중 Medium | Near 4–1 Far, 사용자 승리 | 17 | 18 |
| 상 Hard | Near 0–4 Far, AI 승리 | 17 | 21 |

중 난이도에서 한 포인트 9회, 상 난이도에서 한 포인트 13회 이상 타격이 이어지는 것을 확인했습니다. 종료 후 서브가 다시 시작되지 않고 난이도 버튼으로 새 경기를 시작했습니다. 실행 중 Console 경고·오류는 0이었습니다. 기존 Input Manager 폐기 예정 안내는 Editor 시작 시 1건 표시되며 이번 기능에서 입력 패키지를 변경하지 않았습니다. Mac Universal 개발 빌드를 확인했습니다. Windows 실행과 실제 BLE/외장 IMU 검증은 별도입니다.

AI PR #1 병합 후 참조를 main 커밋 `0eb9f8b6996feac8430aefde20fbc87682439fe8`로 갱신하고 프로젝트 검증, AI 연결 EditMode 4건, 세 난이도 경기·모드 차단 PlayMode 4건을 다시 통과했습니다. 각 난이도에서 실제 리턴·득점·다음 서브·게임 종료를 확인했습니다.

## 캐릭터 스킬 연결

별도 AI 패키지의 `AiSkillPolicy`가 성공한 리턴 직후 Easy 3개 / Medium 2개 / Hard 1개부터 스킬 사용 여부를 판단합니다. 게임 어댑터는 이를 일반 Skill 입력으로 변환하며 게이지·점수·효과를 직접 조작하지 않습니다. 캐릭터별 능력치와 전체 최신 검증은 [월드 캐릭터 문서](world-characters.md)를 참고하세요.
