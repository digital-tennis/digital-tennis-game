# GM-05 가상 라켓 입력과 자동 이동

## 먼저 실행해 보기

Unity **6000.3.26f1**에서 `Assets/Scenes/MatchCourt.unity`를 열고 ▶를 누릅니다. 선택한 캐릭터의 Near와 Far가 공의 예상 타격 위치로 이동하고, 라켓을 휘두르며 공을 주고받습니다. 기본 데모는 **포핸드·백핸드 4회→득점→다음 대각 서브**입니다. `Continuous rally`를 체크하면 의도적인 4회 종료 제한을 해제합니다. 공이 out이거나 두 번 바운스하면 기존 경기 규칙대로 포인트를 끝냅니다.

이 데모 입력은 같은 동작을 재현하는 개발 도구입니다. AI 판단, 실제 BLE 수신, IMU 모션 분류는 각 제품의 후속 작업입니다. 실제 컨트롤러는 **NU40-DK에 외장 IMU를 별도 부착**합니다. 전체 계획은 12일·3명입니다.

## 직접 타격하기

`Demo: racket swings`를 끄면 이동만 자동으로 수행하며 타격은 사용자가 결정합니다. `Demo: auto serve`를 끄면 Space로 서브도 직접 시작합니다. 패널에 `HIT READY`가 표시될 때 해당 선수의 키 또는 버튼을 누릅니다. 범위 밖 입력은 공을 바꾸지 않고 `OutOfReach`, 너무 이른 입력은 `WrongPhase` 등으로 표시합니다.

| 조작 | 동작 |
| --- | --- |
| Space | 정상 서브 |
| Q / W | Near 포핸드 / 백핸드 |
| E / D | Far 포핸드 / 백핸드 |
| Power 슬라이더 | 세기 0~1, 속도 10~22 m/s; 기본 0.35→14.2 m/s, 캐릭터·체력·스킬 보정 전 |
| Aim left/right | 선수의 시점에서 좌우 -1~1→-25°~25° |
| Aim low/high | -1~1→위로 10°~30° |
| F / L | 폴트 / 실제 네트 상단에 접촉하는 렛 서브 |
| R | 한 게임 재시작 |

포핸드·백핸드는 서로 반대 방향의 라켓 애니메이션을 사용합니다. 같은 세기·조준값이면 공의 발사 속도는 같습니다. 백핸드라는 이유로 사용자의 조준을 반전하지 않습니다. 현재는 간단한 라켓 모형과 캡슐 캐릭터를 사용합니다.

## 문제 상황과 구현해야 할 결과

선수는 공을 쫓아 자동으로 움직입니다. 입력을 받았다는 이유만으로 멀리 있는 공을 순간 이동시키거나 점수를 올리면 안 됩니다. 입력이 현재 공의 타격 기회에 속하고, 타격자가 맞고, 공이 실제로 닿는 범위인지 먼저 검사합니다. 성공하면 **공의 현재 위치를 유지한 채 속도만 변경**하고 마지막 타격자를 갱신합니다.

| 타격 조건 | 기준 |
| --- | --- |
| 상태 | `Rally`이며 마지막 타격자의 상대 |
| 공 | 현재 발사된 공이며 정지하지 않음 |
| 자신의 코트 | Near z < -0.2 m, Far z > 0.2 m; 네트 안에서 발사하지 않도록 여유 확보 |
| 높이 | 공 중심 y = 0.2~2.5 m, 경계 포함 |
| 도달 거리 | 선수와 공 사이 **기본 코트 평면 거리 ≤1.5 m** (캐릭터 수비/스킬 보정), 경계 포함; 높이는 별도로 검사 |
| 시점 | 같은 PC에서 수신한 후 0.25초 이내; 미래 시각·이전 rally/shot은 거절 |
| 중복 | `(player, sessionId, eventId)` 최근 64개 기억; 성공과 실패를 모두 소비 |
| 권위 | authoritative 공을 소유한 실행만 물리·캐릭터 위치를 변경 |

공이 상대에게 반환되면 새 shotId를 부여합니다. 같은 incoming shot에 대한 반복 입력은 다시 타격하지 않습니다. 득점·재서브 후에도 이전 shotId를 담은 입력을 재생하지 않습니다. 소스가 연결 세션을 바꾸면 같은 eventId도 새 이벤트로 구분합니다. 이미 64개 이상 지난 오래된 입력도 타격 유효 시간과 shot 검사를 통과해야 합니다.

## 입력과 출력 계약

`RacketInput`은 센서 패킷이 아닌 **게임용으로 정규화된 값**입니다. `SubmitInput`이 공통 경계이며 키보드·화면 버튼·데모가 모두 이 경계를 통과합니다. 미래 BLE 어댑터도 같은 메서드를 호출하면 됩니다.

| 필드 | 의미 |
| --- | --- |
| Player / Stroke | Near·Far, Forehand·Backhand |
| SessionId / EventId | 0이 아닌 소스 세션과 이벤트 식별자 |
| Power01 / AimX / AimZ | 각각 [0,1], [-1,1], [-1,1]; 범위 밖·NaN·무한대 거절 |
| ReceivedAt | PC 단조 증가 시계의 수신 시각; `Time.realtimeSinceStartupAsDouble`과 같은 기준 |
| RallyId / IncomingShotId | 입력을 받았을 당시의 포인트·공 발사 식별자 |
| SwingResult | Hit / Duplicate / Invalid / Stale / WrongPhase / OutOfReach 등 |

BLE 어댑터는 수신 시각과 당시 rally/shot을 기록하고, 재전송을 새 입력으로 만들지 않아야 합니다. MCU의 `deviceTimeMs`를 PC 시계에서 빼면 안 됩니다. 패킷 파싱·모션 인식·왼손 좌표 변환은 기존 프로토콜/펌웨어/SDK 책임입니다. 이번 코드는 그 기능을 중복 구현하지 않습니다.

속도 크기는 `10 + 12 × power01`, 좌우각은 `aimX × 25°`, 위로 드는 각은 `20° + aimZ × 10°`입니다. 선수 로컬 좌표로 방향을 만든 후 Near는 그대로, Far는 y축 180° 회전합니다. x와 z가 함께 반전되므로 두 선수 모두 자기 앞쪽으로 타격합니다. 이 코트 방향 변환은 게임에서 한 번만 합니다.

예: power=0.5, aimX=aimZ=0이면 Near는 +z, Far는 -z 방향으로 위로 20°, 속도 16 m/s입니다. 3 m 떨어진 공에 Q를 누르면 Miss이며 나중에 공이 가까워져도 같은 이벤트 재전송은 Hit로 바뀌지 않습니다.

## 자동 이동을 구현하는 순서

1. 새 shotId가 생기면 실제 `BallSimulation`을 복사합니다. 복사본만 60Hz로 진행하므로 예측은 실제 공·사건·점수를 바꾸지 않습니다.
2. 첫 바운스 후 공이 약 1 m 높이로 올라오는 위치를 찾습니다. 낮은 궤적에는 허용 높이 안에서 가장 가까운 표본을 사용합니다. 3초 안에 없으면 기본 대기 위치를 사용합니다.
3. x를 단식 코트 ±4.115 m, z를 자기 진영의 네트에서 0.8 m~베이스라인 11.885 m로 제한합니다. 예측 위치가 상대 코트에 있으면 자기 네트 쪽 경계로 제한합니다.
4. 프레임당 최대 `5 × deltaTime` m만 움직입니다. 리턴한 선수는 자신의 중앙 대기 위치로 돌아갑니다. 득점·폴트·렛 후 서브를 준비할 때만 시작 위치를 다시 배치합니다.
5. 이동해도 타격은 자동 성공하지 않습니다. 실제 공 위치로 위 타격 조건을 다시 검사합니다.

## 검증 방법

Editor를 저장하고 닫은 뒤 `bash tools/unity.sh check`, `test-edit`, `test-play`를 실행합니다. EditMode는 속도·각도와 Far 좌표 대칭, 범위 경계, 중복/지연/잘못된 값, 5 m/s 제한, 예측이 실제 공을 바꾸지 않는지 확인합니다. PlayMode는 두 선수가 각각 2 m 이상 이동하며 총 6번 타격하고, 두 종류 스트로크를 사용하고, 점수·다음 서브·다음 리턴까지 이어지는지 검사합니다. 너무 이른 입력의 재전송과 이전 shot 입력, 비권위 실행의 이동 제한도 검사합니다.

Unity 화면에서는 자동 데모를 관찰한 뒤 `Demo: racket swings`를 끄고 Q/W/E/D로 직접 타격합니다. Console의 `TENNIS_SWING` 기록에서 선수·스트로크·성공/실패·incoming shot을 볼 수 있습니다. 네트·out·두 번째 바운스는 계속 실제 물리 및 기존 점수 규칙을 사용합니다. 임의의 세기·조준 조합이 항상 유효한 리턴을 보장하지는 않습니다.

기존 Forehand=1/Backhand=2를 유지하고 Smash=3, Volley=4, Slice=5, Lob=6을 추가했습니다. 스매시는 공 높이 1.75m 이상, 발리는 바운스 0회 조건이 추가되며 서브 첫 바운스 전 리턴은 계속 금지합니다. 기본 이동/샷 값 위에 능력치·체력·스킬을 적용합니다. [조작·규칙·CSV 상세](world-characters.md)를 참고하세요.
