# 단식 경기: 포인트 → 게임 → 세트 → 매치

## 목표와 기본 형식

플레이어가 한 게임을 이겼다고 전체 경기가 끝나면 안 됩니다. 현재 기본 경기는 **3세트 중 2세트 선승**입니다. 세트별 게임 수와 타이브레이크 결과를 보관하고 최종 결과 화면에 표시합니다. 1인 플레이·연습·온라인 모두 같은 순수 규칙을 사용합니다.

기준은 [ITF Rules of Tennis 2026](https://www.itftennis.com/media/7221/2026-rules-of-tennis-english.pdf)의 규칙 5–7(점수), 10(엔드 교대), 14(서비스 순서), 17·20·22(서브·폴트·렛)입니다. 기본 형식은 마지막 세트까지 같은 7점 타이브레이크 세트입니다. 특정 대회의 최종 세트 전용 규정은 자동 적용하지 않습니다.

## 구현할 동작과 예제

| 상황 | 기대 결과 |
| --- | --- |
| 0–0에서 Near가 포인트를 이김 | 포인트 15–0. 게임·세트는 그대로 |
| 40–40 | 듀스. 한 포인트를 이기면 AD, 상대가 다음 포인트를 이기면 다시 듀스 |
| AD인 선수가 다음 포인트를 이김 | 그 선수의 게임 수 +1. 표시 대기 후 포인트 0–0으로 새 게임 |
| 게임 5–5에서 Near가 한 게임 이김 | 6–5. 세트는 아직 종료하지 않음 |
| 위 상태에서 Near가 다시 게임을 이김 | 7–5로 세트 승리. 필요한 세트가 남으면 게임·포인트를 0–0으로 초기화 |
| 게임 6–6 | 타이브레이크. 포인트를 0·1·2…로 표시하며 15·30·40/AD로 표시하지 않음 |
| 타이브레이크 6–6 → 7–6 | 아직 승리 아님. 8–6이면 7–6 게임 스코어로 세트 승리 |
| 세트 1–0에서 첫 번째 선수 승리 | 다음 세트 계속. 매치 결과 화면으로 넘어가지 않음 |
| 세트 1–1 | 세 번째 세트 진행 |
| 세트 2–0 또는 2–1 | 매치 종료. 추가 입력·공 사건으로 점수 변경 금지 |

서브·리턴 실패, 아웃·두 번째 바운스·더블 폴트의 포인트 승자는 기존 `TennisMatch`가 결정합니다. 스킬·애니메이션·파티클은 포인트를 부여하지 않습니다. 종료된 랠리 ID는 다음 게임/세트에서도 다시 득점할 수 없습니다.

## 서버, 좌우 서비스 코트, 엔드

- 한 일반 게임 안에서는 같은 선수가 서브하고, 다음 게임에서는 상대가 서브합니다. 세트 경계를 넘어도 이 순서를 유지합니다. 현재 최초 서버는 Near로 정해져 있으며 토스·최초 선택 UI는 별도입니다.
- 각 게임과 타이브레이크는 오른쪽 서브로 시작해 포인트마다 좌우를 교대합니다. 폴트와 렛에서는 서버·좌우·엔드·포인트를 유지합니다. 두 번째 서브의 렛은 첫 폴트 기록을 지우지 않습니다.
- 타이브레이크 첫 서버가 1포인트, 상대가 2포인트, 이후 각각 2포인트씩 서브합니다. 순서는 A / B / B / A / A / B / B…입니다. 다음 세트 첫 서버는 타이브레이크 첫 서버의 상대입니다.
- 각 세트의 1·3·5…번째 게임 후 엔드를 교대합니다. 세트가 짝수 게임으로 끝나면 그 경계에서 추가 교대를 하지 않습니다. 타이브레이크에서는 매 6포인트 후 교대하고, 7–6 세트 종료 후에도 다음 세트를 위한 엔드 교대를 처리합니다. 같은 경계에서 중복 회전하지 않습니다.
- 교대는 득점 표시·필요한 공 회수가 끝난 다음 포인트 준비에서 처리합니다. 현재는 위치·방향·카메라를 전환하며 걸어서 코트를 바꾸는 전용 연출과 공식 휴식 시간은 없습니다.

`Near/Far`와 온라인 `host/guest`는 선수 **ID**입니다. 엔드 교대 시 캐릭터·스킬·입력 권한을 서로 바꾸지 않습니다. `Match.EndOf(player)`로 물리적 위치를 구하고 `ShotContext.HitterEnd`로 착지를 판정합니다. 라켓의 로컬 조준은 현재 엔드를 기준으로 한 번만 월드 좌표로 변환합니다. 각 카메라는 자신의 현재 엔드에 붙으며 항상 자기 선수가 화면 아래에 보입니다.

AI 패키지는 기존의 일관된 Near/Far 좌표를 그대로 받습니다. Unity 어댑터가 엔드 교대에 맞춰 관측·이동 목표를 변환하고, AI 차례에는 정규화된 Serve 입력을 보냅니다. 온라인 게스트의 서브도 같은 어댑터를 통과하고 현재 서버·rallyId·shotId를 호스트가 확인합니다. 게스트는 물리·득점·서비스 순서를 독자 계산하지 않습니다.

## 빌드 없이 경기 형식 바꾸기

배포 기본 파일은 `Assets/StreamingAssets/Balance/rules.csv`입니다. 첫 실행 때 사용자 데이터의 `Balance/rules.csv`로 복사합니다. 실제 경로는 설정 화면에 표시합니다. 검증 실행은 `-dt-rules-file /absolute/path.csv`로 별도 파일을 지정해 사용자 파일을 건드리지 않습니다.

```csv
key,value,description
best_of_sets,3,최대 세트 수
games_per_set,6,세트의 최소 게임 수
tie_break_at,6,동률 타이브레이크 진입 게임 수
tie_break_points,7,타이브레이크 목표 포인트
```

키 앞에 공백을 넣지 마세요. 저장소의 원본 CSV를 복사해 값 열만 바꾸는 것이 안전합니다.

| 키 | 허용 값 | 기본값 |
| --- | --- | --- |
| `best_of_sets` | 3 또는 5. 각각 2세트·3세트 선승 | 3 |
| `games_per_set` | 6 또는 단축 형식 4 | 6 |
| `tie_break_at` | 기본 6. 단축 형식은 4 또는 3 | 6 |
| `tie_break_points` | 7 또는 10. 항상 2포인트 차 필요 | 7 |

프로젝트 기본은 6게임·6–6 진입·7점입니다. 단축 형식과 10점 설정은 사용자 지정 경기 형식으로 표시·운용하며 모든 공식 대회와 동일하다고 해석하지 않습니다. CSV 형식은 한 경기의 시작 시 고정합니다. F5로 새 파일을 읽어도 진행 중인 경기의 세트 목표가 바뀌지 않으며, 새 경기·재경기 때 적용합니다. 잘못된 키, 중복, 누락, 소수, 허용하지 않는 조합은 거부하고 마지막 정상 설정을 유지합니다. 게임·캐릭터 밸런스의 기존 안전한 서브 경계 적용과 별개입니다.

## 점수판과 결과

상단 첫 줄은 포인트, 두 번째 줄은 세트와 현재 게임입니다. 타이브레이크에는 목표 포인트도 표시합니다. 서브 버튼은 실제 자신의 서비스 차례에만 나타나며 상대 차례에는 기다리라는 안내를 표시합니다. 세트 승리만으로 결과 화면에 들어가지 않습니다. 최종 결과는 `세트 2–0 | 7–6 (TB 8–6) / 6–0`처럼 기록합니다.

스냅샷의 기존 `points`는 **현재 게임/타이브레이크**의 포인트입니다. 신규 `score`는 형식·게임·세트·완료 세트별 게임/TB 결과·경기 전체 누적 포인트·엔드 교대 횟수·게임 첫 서버를 담습니다. `winner`는 매치 승자만 담습니다. 재접속 체크포인트도 이 상태를 포함하고, 게스트는 부분·모순된 스냅샷을 거부합니다. 양쪽 게임과 서브 입력을 허용하는 새 서버를 함께 사용해야 합니다.

## 검증

2026-10-16 Mac / Unity 6000.3.26f1에서 다음을 확인했습니다. 이전 문서의 4–0/4–1은 세트 도입 전 한 게임의 누적 포인트입니다.

- EditMode **123/123**, PlayMode **31/31** 통과. 게임 승리 후 HUD 보강 뒤 FrontEnd **4/4**를 다시 통과했습니다(전체 수에 중복 합산하지 않음). 최종 프로젝트 check와 Mac 빌드도 성공했습니다.
- 순수 규칙: 듀스·2포인트 차, 5–5→7–5, 6–6→타이브레이크, 6–6→7–6에서 미종료·8–6에서 승리, 7점/10점 목표, 3/5세트 형식, 1–1 뒤 결정 세트, 서비스 순서, 엔드 교대, 게임 경계의 이전 랠리 중복 거부, CSV 차기 경기 적용과 잘못된 스냅샷 거부를 검증했습니다.
- 실제 공 물리 PlayMode: 정상 입력으로 **48포인트 / 6–0, 6–0 / 세트 2–0**까지 완료하고 재시작하지 않는지 확인했습니다. AI 상·중·하 모두 두 서비스 게임을 진행했으며 각 난이도의 AI가 실제 서브와 리턴을 수행했습니다.
- 두 독립 Mac 실행 파일(PID 52325 / 52326), 일반 창, 정상 입력 어댑터를 사용하는 명시적 CLI 검증 소스로 **87포인트 / 세트 2–0 / 7–6(TB 8–6), 6–0**의 동일한 최종 결과를 확인했습니다. 앞선 한 게임에서 끝내지 않고 다음 세트와 최종 결과 화면까지 진입했습니다. 포인트나 공 위치를 직접 설정하지 않았습니다.
- 양쪽 엔드 교대 **12회**, 각 선수 리턴 **12회**, 최대 랠리 **6회**. 게임/타이브레이크의 호스트·게스트 서브, 실제 UI 레이캐스트 **8회/5회**(콜백 대체 0회), 재접속 epoch **2**, 스킬 최대 3개·양측 실제 발동, 심판/회수, CSV 재로드·파티클 회귀를 함께 통과했습니다.
- 양쪽 실행·통신·시점·미러 이동·선수 위치/타격·캐릭터 상태 오류 **0개**, 게스트 물리 tick **0**. 두 프로세스 모두 종료 코드 0입니다.
- 게임 자체 ScreenCapture PNG **46장**과 JSON 상태를 저장했습니다. 안정된 타이브레이크 6–6 화면과 최종 MATCH COMPLETE 화면을 직접 확인했습니다. 전환 경계의 PNG/상태 메타데이터에는 UI 갱신 순서에 따른 한 프레임 차이가 있을 수 있습니다. 운영체제나 다른 앱 화면은 캡처하지 않았습니다.

독립 실행 입력은 자동 검증 소스이며 OS 키보드 수동 조작 증거와 구분합니다. 이번 OS 창 조작은 Mac 잠금으로 제한되었습니다. 같은 Mac의 로컬 WebSocket 릴레이 검증이며 두 물리 PC·WAN·직접 P2P·Windows 실기·외장 IMU 보드의 검증은 별도입니다. 기본 형식의 전체 매치를 실행했고 5세트/단축/10점 형식은 순수 규칙 테스트로 확인했습니다.

현재 자동 이동·단식 타격 모델에는 선수의 신체/네트 접촉, 풋 폴트, 고의 방해 및 복식 규칙이 없습니다. 공 크기·균일한 네트 높이는 기존 게임용 물리 근사값입니다.
