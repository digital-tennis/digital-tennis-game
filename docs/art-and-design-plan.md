# 캐릭터와 게임 디자인 개선 계획

Digital Tennis의 캐릭터 모델, 테니스 동작, 코트, 카메라, 메뉴와 경기 화면의 품질을 높이기 위한 작업 계획입니다. 국가별 개성이 뚜렷한 스타일화된 3D 아케이드 테니스를 목표로 합니다. 한국·일본 선수 2명과 서울 코트 1개에서 품질 기준을 확정한 뒤, 기존 15명과 15개 코트로 확장하는 순서를 권합니다.

전체 프로젝트의 조건은 **12일·3명**, **NU40-DK에 외장 IMU 별도 부착**, Unity PC 게임과 1인·온라인 2인 플레이입니다. 완성형 모델 15명과 모든 전용 동작을 새로 제작하는 공수는 에셋 확보와 시범 제작 결과로 산정합니다. 아래 순서는 추가 12일 일정을 확정한 것이 아닙니다.

## 현재 구현과 목표

현재 캐릭터는 기본 도형, 개별 배색, 간단한 관절 회전과 스킬 포즈로 구성됩니다. 로고·타이틀·세계지도 선택·경기·결과 화면과 실제 경기 판정은 구현되어 있습니다. 아트 교체는 이 흐름을 바탕으로 진행합니다.

현재 구현의 선수 선택 화면입니다.

![현재 세계지도 선수 선택 화면](images/front-end/06-world-player.png)

| 영역 | 개선할 내용 | 먼저 확인할 결과 |
| --- | --- | --- |
| 캐릭터 | 얼굴·헤어·손·운동복·신발·라켓을 갖춘 모델, 선수별 체형과 실루엣 | 이름표 없이도 두 선수를 구별할 수 있음 |
| 테니스 동작 | 준비·이동·서브·6종 타격·득점·실점 동작 | 발 미끄러짐과 손에서 라켓이 떨어져 보이는 현상을 줄임 |
| 경기 카메라 | 선수·공을 읽기 좋은 거리와 각도, 절제된 전환 | 양쪽 시점에서 공과 필요한 코트 영역을 계속 확인할 수 있음 |
| 코트·조명 | 바닥 재질, 부드러운 그림자, 벤치·관중석·도시 배경 | 배경이 공·라인·선수와 시각적으로 구분됨 |
| 메뉴·HUD | 초상과 선수 소개, 서브 표시, 점수·스킬 사용권 강조 | 다음 행동과 현재 경기 상태를 바로 이해할 수 있음 |
| 타격 피드백 | 성공한 타격의 짧은 효과·소리와 연습용 안내 | 실제 타격 성공과 입력 실패를 구분할 수 있음 |

## 캐릭터 제작 방법

골격은 모델을 움직이는 뼈대이고, 스키닝은 몸 표면이 뼈대를 따라 변형되도록 연결하는 작업입니다. Unity의 Humanoid Avatar는 서로 다른 사람형 모델에 같은 기본 애니메이션을 적용하는 기준입니다. 유효한 Avatar 설정이 필요합니다. [Unity Humanoid 리타기팅](https://docs.unity3d.com/6000.3/Documentation/Manual/Retargeting.html)

| 방법 | 장점 | 필요한 작업 |
| --- | --- | --- |
| 기존 캐릭터 에셋 수정 | 기본 모델·골격 제작 시간을 줄일 수 있음 | Unity 6.3와 Built-in 재질 호환, 골격, 포함 동작, 수정 범위와 라이선스 확인 |
| Blender 직접 제작·외주 | 얼굴·의상·실루엣을 페르소나에 맞추기 좋음 | 원화, 모델링, 골격, 스키닝, 동작, 게임 적용까지 제작 |
| 기본 모션 활용 | 대기·걷기 등 공통 동작을 빠르게 시험할 수 있음 | 테니스 스윙·손 그립·발 위치를 전용 동작으로 보정 |

Mixamo는 사람형 캐릭터의 기본 모션 후보로 검토할 수 있으며 공식 FAQ에서 게임을 포함한 상업 프로젝트 사용을 안내합니다. 필요한 테니스 동작의 제공 여부와 원본 파일 공개 조건은 도입 전에 확인합니다. [Adobe Mixamo FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html)

원화와 색상 시안이 확정되어도 게임용 모델·골격·스키닝·동작 검수가 필요합니다. 에셋을 선택할 때는 실제 경기 카메라와 선택 화면의 확대 화면 양쪽에서 확인합니다.

### 국가와 개인의 특징

15명은 기존 [월드 캐릭터 설계](world-characters.md)의 가상 성인 페르소나를 유지합니다. 국가는 의상·공간·생활 배경의 참고 자료이고, 얼굴·체형·성격은 각 개인의 설정으로 설계합니다. 기존 게임 인물의 얼굴·의상·로고를 복제하지 않습니다.

| 예시 | 의상과 색의 방향 | 동작과 공간의 방향 |
| --- | --- | --- |
| 한국 한서윤 | 현대 운동복에 한복의 절개선과 단청의 색 일부 반영 | 절제된 준비 자세, 강변 새벽과 한옥 지붕의 리듬 |
| 일본 아오야마 렌 | 남색 운동복과 접힌 면을 닮은 선 | 짧고 빠른 스텝, 종이 조형과 교토의 푸른 저녁 |
| 모로코 살마 암라니 | 청록·모래색과 타일 기하학의 부분 무늬 | 안정된 수비 자세, 아치와 타일이 보이는 공간 |

공통 조명과 재질 기준을 사용하면서 헤어, 체형, 의상 절개, 소품과 표정으로 구분합니다. 시범 선수 2명에서 수정 기준을 확정하고 모로코를 포함한 나머지 선수로 확장합니다.

### 모델과 애니메이션 연결

1. 기본 자세의 모델과 공통 골격을 준비하고 손·어깨·무릎 변형을 확인합니다.
2. 손의 라켓 장착 위치를 정하고 준비 자세와 좌우 이동부터 연결합니다.
3. 서브·포핸드·백핸드·스매시·발리·슬라이스·로브를 연결합니다. 준비→임팩트→회복 구간을 구분합니다.
4. 이동 애니메이션 사이의 전환을 만들고, 필요하면 손·발의 위치를 보정하는 IK를 추가합니다.
5. 득점·실점·선택 포즈와 캐릭터별 스킬을 제작합니다. 스킬은 기존 1.2초 안에서 준비·집중·분출·복귀를 구성합니다.

공통 동작을 공유하되 대기 자세·표정·고유 스킬은 개별화합니다. 현재 `CharacterPresentation`의 관절 직접 회전과 `RacketAvatar`의 라켓 회전은 새 Animator와 같은 뼈를 동시에 제어하지 않도록 정리해야 합니다.

실제 이동은 기존 자동 이동 시스템이 담당하고, 모델은 하위 오브젝트에서 움직임을 표현합니다. 애니메이션 자체가 선수를 이동시키는 루트 모션을 적용할 경우 기존 위치 제어와 충돌할 수 있으므로 초기 구성은 위치 제어를 게임에 둡니다. [Unity 루트 모션 설정](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Animator-applyRootMotion.html)

## 화면과 경기 디자인

현재 남색·라임색 브랜드, 한글 글꼴, 세계지도 선택 흐름을 기준으로 버튼·여백·글자 크기와 선택 표시를 통일합니다. 경기 중 공·코트 라인·스코어·스킬 사용권이 배경과 효과보다 먼저 읽혀야 합니다.

- 선택 화면은 선수 초상 또는 확대 모델, 이름, 국가, 플레이 스타일, 6개 능력치를 일정한 위치에 배치합니다.
- 경기 HUD는 서브하는 선수 표시, 점수와 판정, 사용권 0~3개, 체력, 다음 입력 안내의 우선순위를 정합니다.
- 연습 모드는 타격 가능한 순간과 실점 이유를 알려줍니다. 안내는 실제 판정 상태를 읽고 새로운 점수나 입력 성공을 만들지 않습니다.
- 국가별 코트는 배경 건축·바닥 무늬·조명 시간대로 차별화하고, 같은 크기의 경기 경계와 네트 판정을 유지합니다.
- 카메라는 Near와 Far 양쪽에서 확인합니다. 상대 시점 때문에 공유 좌표를 다시 뒤집거나 입력 방향을 두 번 반전시키지 않습니다.
- 스킬 카메라는 공·위치·점수를 보존한 상태로 연출 후 경기 시점에 복귀합니다. 연출 움직임 줄이기와 효과 밀도 설정을 유지합니다.

초기 개선은 현재 Built-in Render Pipeline에서 모델·재질·조명과 구도를 조정합니다. URP 전환은 필요한 효과와 에셋 호환성을 시범 화면에서 비교한 뒤 별도 작업으로 판단합니다.

## 경기와 온라인 연결 원칙

아트와 애니메이션은 확정된 경기 결과를 표현합니다. 캐릭터 외형이나 라켓 메시의 충돌이 공을 다시 발사하거나, 애니메이션 이벤트가 점수를 올리는 구조로 바꾸지 않습니다.

- 능력치·타격 범위·이동 속도·체력·스킬 배율은 기존 [CSV 밸런스 구조](gameplay-balance.md)를 사용합니다. 외형 변경으로 판정이나 능력치가 달라지지 않아야 합니다.
- 타격은 `PlayerInputAdapter`와 기존 입력 검사를 통과합니다. 키보드와 향후 외장 IMU 입력은 같은 경계를 사용합니다.
- 호스트가 물리·규칙·스킬을 결정하고, 손님은 스냅샷의 위치·실제 스윙 ID·스킬 ID와 경과 시간으로 표현합니다.
- 새 경기·재접속의 과거 동작과 파티클을 다시 재생하지 않습니다. 자세한 효과 계약은 [파티클 문서](gameplay-effects.md)를 따릅니다.

## BGM과 함께 완성하는 첫 제작 범위

첫 제작 범위는 한국·일본 선수 2명, 서울 코트 1개, 메뉴·경기·결과의 음악 3종입니다. 기존 15명 선택 흐름을 유지하면서 이 조합의 품질 기준을 먼저 확정합니다. 기본 경기곡은 득점마다 재시작하지 않고, 스킬은 짧은 강조음과 음악 음량 변화로 연결합니다.

음악 후보 확보, A/B 청음, 장면별 전환, AudioMixer, 외부 CSV·음원 교체와 공개 저장소 권리는 [음성·BGM 제작 및 청음 작업안](audio-production-research.md)에서 관리합니다. 국가별 완성곡 15개는 공통 테마와 반복 구조를 확정한 뒤 확장합니다.

## 3인 작업 분담과 완료 기준

숙련자는 게임과 표시 시스템의 경계를 맡고, 나머지 두 명은 에셋·화면 구성과 검수를 분담하는 안입니다. 담당 B의 모델 제작 경험이 부족하면 기존 에셋 수정이나 외주를 함께 검토합니다.

| 담당 | 주요 작업 | 전달할 결과 |
| --- | --- | --- |
| A 게임 연결 | 모델 교체 구조, Animator, 타격 시점 표현, 오디오 연결, 온라인 검증 | 경기 로직과 분리된 표시 구성 및 재현 가능한 검사 |
| B 아트 구성 | 선수·라켓·코트 리소스 선정과 수정, 재질·조명, 권리 자료 정리 | 선수 2명과 코트 1개의 일관된 시범 화면 |
| C UI와 검수 | 초상·선택 화면·HUD, 청음 비교 화면, 검수 기록 | A/B 선택 결과와 실제 게임 화면·청음 기록 |

P0는 첫 제작 범위를 완성하는 작업이고 P1은 기준을 확정한 뒤의 확장 작업입니다. 완료 기준을 충족하면 다음 단계로 넘어갑니다.

| 순서 | 작업 | 의존 관계 | 완료 기준 |
| --- | --- | --- | --- |
| P0 1 | 아트 기준과 에셋 결정 | 기존 페르소나·현재 경기 화면 | 두 선수의 실루엣·배색·기본 자세, 모델 호환성과 공개 범위 확정 |
| P0 2 | 기본 모델과 동작 연결 | P0 1 | 이동·서브·6종 타격을 실제 랠리에서 확인하고 손·발의 어긋남 기록 |
| P0 3 | 코트·카메라·HUD 개선 | P0 2 | 양쪽 시점에서 선수·공·라인·점수가 읽히고 메뉴로 정상 복귀 |
| P0 4 | BGM 청음과 연결 | 장면별 브리프·음원 권리 확인 | 6개 후보 비교, 채택한 곡의 반복·전환과 음량 설정 확인 |
| P0 5 | 통합 검수 | P0 2~4 | 1인·온라인 경기, 스킬·일시정지·재접속·결과 화면을 함께 확인 |
| P1 | 15명·15개 코트로 확장 | P0 품질 기준 확정 | 공통 기준과 개인별 특징을 적용하고 캐릭터별 시각 오류 검수 |

통합 검수에서는 모델 관통·발 미끄러짐·라켓 그립·타격 표현 시점, Near/Far의 상대 동작, 공 가림, 한글 잘림, 반복 음악의 틈, 음량 저장과 중복 재생을 확인합니다. 이전 외형과 새 외형에서 같은 CSV·입력에 대한 경기 판정이 달라지지 않는지도 확인합니다.

목표 PC에서 두 선수·코트·효과·음악을 함께 실행해 프레임 시간과 메모리를 측정합니다. Mac 검증과 실제 Windows PC·외부 네트워크·실물 BLE/IMU 검증은 구분합니다. 원격 확인용 화면은 승인된 방식대로 Mac 잠금을 유지하고 게임 카메라와 UI만 PNG로 저장합니다.
